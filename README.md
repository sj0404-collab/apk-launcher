# APK Launcher

<p align="center">
  <img src="docs/cover.png" alt="APK Launcher" width="100%">
</p>

Нативный (без WebView и HTML) Android-лаунчер: список установленных
приложений, запуск одной кнопкой и **keep-alive**: выбранные приложения
держатся живыми foreground-сервисом, который перезапускает процесс, если он
умирает.

## Возможности

- Полностью нативный UI `MainActivity`: поиск, сетка карточек с иконками и
  версиями, запуск по тапу.
- Тумблер keep-alive на каждой карточке и в списке процессов. Держимые
  приложения не выскакивают поверх лаунчера: пока лаунчер на экране с фокусом,
  авто-подъём не срабатывает, а приложение, которое вы закрыли, не
  «воскрешается» мгновенно (кулдаун и авто-отказ после повторных закрытий).
- Панель живых процессов с keep/запустить прямо из списка.
- Foreground-сервис с ватчдогом, который **не держит CPU постоянно включённым**:
  wake lock берётся только на время самой проверки, а интервал опроса адаптивный —
  2 с, когда ждёт перезапуск, 6 с в спокойном состоянии при включённом экране и
  15 с с выключенным экраном.
- **Мультиоконность**: кнопка «окно» на каждой карточке/процессе открывает
  приложение в соседнем окне (split-screen); лаунчер при этом остаётся в другой
  половине экрана (`resumeWhilePausing`).
- **Мини-окна для приложений**: тумблер «пин» сразу открывает приложение в
  интерактивном уменьшенном окне (весь UI, можно работать внутри — тап не
  разворачивает на весь экран) и держит его так же при авто-подъёме; «мини» —
  открыть любое приложение маленьким окном, «все мини» — все приложения на keep
  сразу каскадом в отдельных мини-окнах.
- **Кнопки прямо поверх окна**: над каждым мини-приложением плавающий оверлей
  с кнопками — `▣` во весь экран, `+`/`−` увеличить/сузить, `◇` сменить
  позицию (углы/стороны/центр), `✕` открепить и скрыть. Управляется тапом, так что жесты
  можно вообще не использовать; требует разрешение «поверх других окон».
- Панель обновлений: приложение сверяет версию с GitHub Releases и предлагает
  скачать APK новой версии.
- Автономное обновление ключа версии: `versionName` берётся из последнего git-тега,
  `versionCode` строится из версии тега и коммитов после него.

## Структура

- `android/` — весь код на Kotlin: нативный UI, `AppKeeper`, `KeepAliveService`,
  `Updater`. Веб-части нет.
- `.github/workflows/release.yml` — сборка релиза и публикация GitHub Release.
- `android/keystore.properties` и `android/keystore/` — локальные файлы для
  release-подписи; они не должны попадать в репозиторий.
- `docs/` — обложка репозитория.

## Сборка

```
cd android
./gradlew :app:assembleDebug    # debug (нужен SDK, адрес в local.properties)
./gradlew :app:assembleRelease  # release; при наличии локального keystore.properties
```

Release получает версию из текущего git-тега. Для подписи нужно создать
`android/keystore.properties` с параметрами локального keystore; файл и ключ
исключены из репозитория. Без этих параметров сборка release останавливается
с ошибкой, а не использует выдуманные значения. Если ключ раньше был опубликован,
его нужно считать скомпрометированным и заменить новым.

## Как выкатить release

Релиз собирается на GitHub Actions, локально ничего собирать не нужно:

1. Закоммитить и запушить изменения в `main`.
2. Открыть `Actions → Release → Run workflow`, указать тег (например `v1.1.2`) и
   при необходимости галочку pre-release.
3. Workflow сам создаст тег, соберёт APK, запушит тег и опубликует релиз с
   заметками из коммитов.

Ключ подписи берётся из secrets репозитория:

```
gh secret set KEYSTORE_BASE64   # base64 от содержимого .jks
gh secret set KEYSTORE_PASSWORD # пароль хранилища
gh secret set KEY_ALIAS         # алиас ключа
gh secret set KEY_PASSWORD      # пароль ключа
```

**Если эти четыре секрета не заданы, workflow собирает debug-APK** и называет
его `apk-launcher-<тег>-debug.apk`, а в заметках релиза ставит предупреждение.
Такой APK подписан отладочным ключом и **не устанавливается поверх** ранее
выпущенной версии: старую нужно удалить и поставить заново. Для нормальных
обновлений секреты обязательны.

`versionName` и `versionCode` считаются gradle из последнего git-тега, поэтому
workflow создаёт тег до сборки — версия в APK всегда совпадает с тегом релиза.
`Updater` проверяет именно опубликованный GitHub Release и показывает его, если
в release есть APK-asset. Одного тега недостаточно.

## Что делает приложение

- `MainActivity` — поиск, сетка карточек, тумблер keep/pin, панель процессов,
  мультиоконный и мини-оконный запуск, автообновление списка процессов с
  адаптивным интервалом (2.5–10 с), проверка обновлений при запуске.
- `AppKeeper` — хранит списки «держимых» и «пинованных» пакетов в
  SharedPreferences и синхронизирует foreground-сервис. Проверка установленных
  пакетов идёт не чаще раза в минуту.
- `KeepAliveService` — ватчдог на wake lock: проверяет `runningAppProcesses` и
  поднимает умерший процесс заново (пинованные — сразу в мини-окно);
  восстанавливает списки после перезапуска системой.
- `Updater` — запрашивает `releases/latest` с GitHub, проверяет наличие APK и
  открывает ссылку на скачивание, если найдена более новая версия. Проверка не
  чаще раза в 6 часов (кнопка «обновить» проверяет принудительно).

## Экономия батареи

Фоновая часть изначально просыпалась каждые 2 с и держала частичный wake lock
бесконечно. Что изменено:

- **Wake lock только на время проверки.** Между тиками CPU может уйти в сон.
- **Адаптивный интервал.** 2 с — только когда перезапуск вот-вот понадобится
  (процесс умер, но кулдаун 15 с ещё не истёк), 6 с — всё живо и экран включён,
  15 с — всё живо и экран выключен. `getRunningTasks` (самый дорогой вызов)
  делается только тогда, когда без него нельзя решить, можно ли перезапускать.
- **Экран.** `ACTION_SCREEN_ON/OFF` пересчитывает интервал сразу, поэтому
  разблокировка экрана не ждёт следующего тика.
- **Состояние пишется в SharedPreferences только при изменениях**, а не раз в
  30 с.
- **Иконки и список приложений кэшируются.** Раньше панель процессов
  пересобиралась целиком каждые 2.5 с вместе с `getApplicationIcon` на каждую
  строку, а список приложений с иконками грузился заново на каждом `onResume`.
  Теперь панель перерисовывается только когда изменились pid/важность/флаги, а
  иконка каждого пакета грузится один раз.
- **Проверка обновлений** ограничена одним запросом в 6 часов вместо запроса
  при каждом запуске приложения.

## Ограничения Android (workarounds)

- Для списка launcher-приложений используется `<queries>` с `MAIN/LAUNCHER`;
  `QUERY_ALL_PACKAGES` не запрашивается.
- На Android 10+ фоновый запуск приложений ограничен, поэтому обёртка использует
  foreground-сервис типа `specialUse` и wake lock только на время проверки.
  Автоматический перезапуск — best effort и зависит от разрешений и текущей
  политики Android.
- На Android 10+ для автоматического перезапуска требуется разрешение
  `SYSTEM_ALERT_WINDOW`; без него Android может заблокировать запуск Activity.
- На Android 13+ запрашивается разрешение `POST_NOTIFICATIONS`.
- Мини-окна (`setLaunchBounds` + best-effort freeform-режим) раскрываются в
  интерактивные свободные окна на системах с поддержкой freeform (планшеты,
  десктоп-режим, Android 15+ с несколькими окнами); на обычных телефонах без
  freeform приложение открывается обычным запуском. Android не даёт
  сторонним приложениям уходить в системный PiP, поэтому именно freeform —
  единственный путь к «приложению в маленьком интерактивном окне».
